# Count 和 Port 是什么？

对应当前 PPT 第 5–6 页。所有计数都在当前交易发生前计算；同一时间戳内使用固定的先后顺序。

**Count 是历史数量。** 本研究同时统计“此前交易了几次”和“此前与几个不同账户交易过”。反复向同一个人转账，会增加交易次数，但不会增加不同对手数。

**Port 是账户给交易对手分配的局部编号。** 按首次接触的顺序，从 0 开始编号。以后再遇到同一个对手，继续使用原来的编号。它不是网络服务端口，也不是全系统统一的账户 ID。

## 第 5 页：逐笔看清楚

S 依次向 A、B、A、C 转账：

| 当前交易 | S 此前转出次数 | S 此前不同接收方数量 | S 给当前接收方的 Port | 是否首次交易对 |
|---|---:|---:|---:|---|
| 第 1 笔：S → A | 0 | 0 | 0 | 是 |
| 第 2 笔：S → B | 1 | 1 | 1 | 是 |
| 第 3 笔：S → A | 2 | 2 | 0 | 否 |
| 第 4 笔：S → C | 3 | 2 | 2 | 是 |

第三笔：A 是老对手，所以仍用 Port 0。第四笔之前，S 已经转了 3 次，但只接触过 A、B 两个不同接收方；新的 C 获得 Port 2。

因此，Count 回答“多少次、多少人”；Port 给当前这位对手一个本账户内部的固定编号。

## 第 6 页：为什么有四个 Count、两个 Port？

对每笔发送方 → 接收方的交易，同时从两端读取历史：

| 特征组 | 发送方这端 | 接收方这端 |
|---|---|---|
| Count | 此前转出次数；此前不同接收方数 | 此前收到转账次数；此前不同发送方数 |
| Port | 发送方给当前接收方的转出编号 | 接收方给当前发送方的转入编号 |

例子中的历史顺序是：S → A、S → B、D → B、S → A。现在要给下一笔 S → B 评分。

- S 此前转出 3 次，接收方有 A、B 两个，因此发送方计数为 **[3, 2]**。
- B 此前收到 2 次转账，发送方有 S、D 两个，因此接收方计数为 **[2, 2]**。
- S 先遇到 A、再遇到 B，因此给 B 的转出 Port 是 **1**。
- B 先收到 S、再收到 D 的转账，因此给 S 的转入 Port 是 **0**。

这笔交易的 **Counts = [3, 2, 2, 2]**；代码按“转入、转出”存储，故 **Ports = [0, 1]**。这些是归一化前的原始数值。

**Counts + Ports** 就是在交易原有的金额、时间等特征之外，同时提供这四个历史计数和两个端口编号。

## Novelty 又是什么？

Novelty 是单独的“首次交易”标记：这对有方向的账户第一次在观察窗口中交易，记为 **1**；此前已经交易过，记为 **0**。第 6 页的 S → B 已经出现过，所以标记为 0。

当对手是新的，当前 Port 等于此前不同对手数；当对手是重复的，Port 小于此前不同对手数。因此，Counts 和 Ports 一起能确定 Novelty，但 Counts 单独无法判断当前对手是否属于以前见过的人。
